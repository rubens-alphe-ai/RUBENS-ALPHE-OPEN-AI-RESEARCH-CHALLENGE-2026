# PROP-EXP-MEM-002 — Structure-only memory handoff test

Frozen before any trial. Its SHA-256 is recorded in the experiment manifest;
any later edit breaks the provenance chain.

## Why this experiment exists

PROP-EXP-MEM-001 was adjudicated REJECT on a confirmed critical fabrication.
Its analysis then showed two design flaws (`../PROP-EXP-MEM-001/PILOT_DESIGN_FLAWS.md`):
the two input states carried different facts, so the score gap measured
content rather than structure; and the structured state leaked its condition
label into the blinded outputs.

MEM-002 asks the question MEM-001 meant to ask, with those flaws removed.

## Hypothesis

Holding information content constant, presenting a project state as named
sections improves blind handoff fidelity over presenting the same facts as
continuous prose, without increasing critical fabrications.

## Conditions

| Manifest condition | Input file | Form |
|---|---|---|
| `baseline` | `STATE_A.txt` | continuous prose, one paragraph per theme, no headings |
| `structured` | `STATE_B.json` | the same items grouped into named sections |

Both files are generated by `scripts/build_mem002_states.py` from `facts.json`
(32 facts). The generator refuses to write unless every fact and its status
phrase appear verbatim in both, and neither contains a condition label. The
file names are neutral on purpose.

Every fact carries an explicit status in both conditions ("verified",
"proposed, not yet run", …), including the fact that no trial of the pending
experiment has run. This addresses the fabrication MEM-001 produced, in both
arms equally, so it is a control and not the variable under test.

## Generation

- generator: `ollama` / `llama3.2:3b`, the same identity for all trials;
- nine pairs, seeds 401–409, one fresh request per trial;
- temperature 0.8, max 2048 output tokens, reasoning channel disabled;
- prompt: `TEST_PROMPT.md`, byte-identical to PROP-EXP-MEM-001's;
- raw outputs stored unchanged with metadata and output hashes.

Temperature is above zero because the adjudicator needs sampling variance; at
0.0 the seeds collapse into duplicates (see MEM-001 `discarded_temperature_zero`).

## Before any output reaches an evaluator

1. confirm the eighteen output hashes are distinct;
2. scan every output for the strings listed in `leak_markers.json` — tokens
   that exist only in `STATE_B.json` — and record every hit;
3. shuffle into blinded packets; the condition map stays private.

A leak does not silently void the experiment, but every hit is reported with
the verdict as a limitation.

## Evaluation

- two independent evaluators from different providers, each in a fresh chat
  with no project context and no repository access;
- one evaluator prompt containing all eighteen shuffled answers, the unchanged
  PCRB-1 rubric (`PCRB1_SCORING.md`) and the output format;
- scorecards ingested through `scripts/ingest_scorecards.py`;
- any critical fabrication reported by only one evaluator goes to a third,
  tool-less checker before adjudication.

## Decision rule

`scripts/adjudicate_evaluations.py`, V4 contract, pilot stage.

With a single generator identity this experiment cannot reach `FINAL_KEEP`,
which ADR-001 reserves for evidence that also spans two generator models,
holdout, calibration and regression. The best available outcome is
`PROVISIONAL_KEEP`. A `REJECT` or `INCONCLUSIVE` is recorded as such.

## Known limits, stated in advance

- one generator, a small local model;
- evaluators are chat models relayed by the operator, not automated;
- a structured JSON input may make answers stylistically recognisable even
  without any leaked label; the leak scan catches copied tokens, not style;
- the snapshot is the same as MEM-001's, so any evaluator who saw MEM-001 is
  not independent for MEM-002.
